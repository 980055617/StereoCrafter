F. CANDIDATE FIXES and their acceptance rule
-------------------------------------------------------------------------------------------------------------------
Classes:
  IDENTITY  accepted iff the pre-encode md5 of the sbs array equals the reference md5 of the same config+resolution
            (576: the reference md5s above; 1792: A3/A4).  Nothing else is claimed for it.
  PIXEL     (md5 differs) rendered losslessly (FFV1), scored with scripts/distill/runs/fulldata_v2/beyond4/score_clip_ll.py
            UNCHANGED, SCORE_STEP=4, on 0301 576x1024, in ONE scorer call together with the reference render
            (outputs/finalcheck_20261004/speed/clips/0301_deliv_g100_T5nat), whose re-score must reproduce 0.399416
            within 0.0001 (else the comparison is void).
            ADOPTED as a speed fix iff |LPIPS(fix) - LPIPS(reference)| <= 0.0005.
            If LPIPS(fix) < reference - 0.0005: reported as a QUALITY-CHANGING setting needing 12-clip validation, NOT
            adopted in the speed headline.  If LPIPS(fix) > reference + 0.0005: rejected.
            Sharpness ratio (ROW sharp / reference sharp) is reported, not gated.

H. HEADLINE (pre-registered computation)
-------------------------------------------------------------------------------------------------------------------
End-to-end speedup at each resolution = process wall-clock(deployed origin, A2/A4) / process wall-clock(deliverable T5
with ALL adopted fixes), same clip, same session, GPU-0 lock held, one render at a time.  Reported beside it:

  - each adopted fix's own saving (paired, same resolution);
  - "service mode" per-clip time (a persistent process: model load and warm-up paid once), if F5's warm-up-once
    process is adopted, stated separately from the single-process CLI number.
  - the share that is pipeline engineering vs Mamba/schedule (origin with the same identity fixes, where measured).
